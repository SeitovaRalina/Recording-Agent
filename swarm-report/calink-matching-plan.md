# Plan: calink-сопоставление — booking-marker пул вместо точного совпадения заголовка   (slug: calink-matching)

## TL;DR

`InterviewMatcher.score()` (`app/services/matching.py`) сегодня отбрасывает событие ДО скоринга,
если заголовок записи с Диска не совпадает побуквенно с заголовком календарного события
(`matching.py:165`). Для calink-бронирований это гарантированный провал: заголовок события,
который генерирует calink («Собеседование в Effective c Лилией Акентьевой (Четова Дарья)»), и
заголовок записи от Телемоста/Лили (общий дефолтный или переименованный вручную) — две независимо
сформированные строки, совпадающие по чистой случайности. Скоринг для таких событий уже работает
отлично (~1.0) — проблема только в гейте.

**Решение — не снимать гейт по заголовку для всех событий (это дыра в безопасности, нашёл
скептик), а добавить второй, узкий путь входа в пул: событие проходит по времени, минуя сверку
заголовка, ТОЛЬКО если в его описании есть booking-маркер (`calink.ru`/`calendly.com`/`cal.com`)**
— именно это независимо подтверждает, что событие реально забронировано кандидатом, а не
случайное совпадение по времени. Точное совпадение заголовка остаётся основным путём для всего
остального (Антон, прямые встречи Лили без calink, технические консультации).

Заодно: регекс-баг (`INTERVIEW_PATTERN` не ловит «собеседования», только «собеседование» —
падежное окончание не совпадает), и опасный существующий инструмент
`tools/setup/rematch_calendar_events.py`, который после этого изменения начнёт считать ПРАВИЛЬНЫЕ
calink-матчи ложными и откатывать их в `FOUND` — чинится в той же задаче, иначе это мина для прода.

## Acceptance criteria

- `app/services/matching.py: score()` строит пул `compatible` из двух источников: (1) как сегодня
  — точное совпадение нормализованного заголовка + окно времени ±15 мин; (2) НОВОЕ — событие
  попадает в пул по ТОЛЬКО окну времени ±15 мин, если `BOOKING_PATTERN.search(event.description)`
  (т.е. есть `calink.ru`/`calendly.com`/`cal.com`) — без сверки заголовка. Дедуп по
  `(calendar_id, uid, recurrence_id)` как сейчас, если событие подходит под оба пути — не
  дублируется.
- Защитная граница (ответ на HIGH-1 скептика): событие БЕЗ booking-маркера и с несовпадающим
  заголовком НЕ попадает в пул ни при каких условиях — чистое совпадение по времени недостаточно
  само по себе. Существующий тест
  `test_reported_non_recruiting_title_cannot_match_other_event` (заголовок записи "Не рекрутинг
  встреча" vs событие "Встреча на 30 минут (Иван Иванов)" БЕЗ calink/calendly-ссылки в описании,
  то же время) продолжает возвращать `NO_COMPATIBLE_EVENT` — тест не переписывается на другой
  сценарий, он остаётся верным как есть, потому что новый путь входа требует booking-маркер,
  которого в этом фикстуре нет.
- Защита от full-day/отпускных записей (HIGH-3 скептика): ни exact-title, ни booking-marker путь
  не принимают в пул событие с длительностью ≥ 20 часов (all-day/многодневные блоки); добавить
  явную проверку длительности события перед добавлением в `compatible` по любому из двух путей.
  Тест с all-day-событием в тот же день, что и реальная запись — пул не раздувается.
- `_score_event` (сигналы и веса NAME_PATTERN/INTERVIEW_PATTERN/BOOKING_PATTERN/time_overlap/
  has_telemost_url) НЕ меняются — скоринг уже работает правильно для реальных calink-случаев.
  `confidence_threshold` (0.7) не меняется.
- `INTERVIEW_PATTERN` регекс-баг исправлен: искать основу `собеседован` вместо полного слова
  `собеседование`, чтобы ловить все падежные формы («собеседования», «собеседований»,
  «собеседованием» и т.д.), не трогая `интервью|interview|candidate`.
- Реальный calink-кейс (Четова Дарья, 2026-09-21: заголовок события «Собеседование в Effective c
  Лилией Акентьевой (Четова Дарья)» + `calink.ru` в описании, заголовок файла НЕ совпадает —
  ни в варианте дефолтного имени Телемоста, ни в варианте «Чегова Дарья DM Junior с Лилией
  Акентьевой.webm») — событие входит в пул через booking-marker путь, скоринг даёт confidence
  около 1.0, `manual_review_required=False`.
- Реальный кейс консультации (Денис Васильев / Михаил Кононенко: заголовок файла точно совпадает
  с событием, в описании нет calink/calendly-ссылки) — остаётся `LOW_CONFIDENCE`, не
  авто-матчится и не ломается через `NO_COMPATIBLE_EVENT`. Веса сигналов под эти кейсы НЕ
  подгоняются (нет подтверждения рекрутера, что это вообще собеседования).
- Реальный кейс «голой» calink-ссылки без параметра `45min` (заголовок события буквально «Ссылка
  для собеседования с Лилией Акентьевой», без calink.ru в описании, без имени/почты кандидата) —
  заголовок файла и события СОВПАДАЮТ (как и раньше), событие проходит через exact-title путь,
  скоринг после фикса regex даёт `time_overlap(0.35) + has_telemost_url(0.05) + interview_keywords
  (0.05)` = 0.45, по-прежнему ниже порога → `LOW_CONFIDENCE`. Это ожидаемо, не баг: у этого типа
  calink-ссылки нет машиночитаемых данных о кандидате вообще — чинить скорингом нечего, только
  честно уходит на уточнение у рекрутера (лучше, чем сегодняшнее ручное переименование + ручная
  заливка в Synology).
- Существующее поведение Антона и прямых встреч Лили (без calink, заголовок файла == заголовок
  события) не регрессирует — тот же или лучше confidence.
- `tools/setup/rematch_calendar_events.py`: `title_mismatch`-эвристика (`normalize_title(
  recording.calendar_event_summary) != parsed.normalized_title`, строки ~41-46) после этого
  изменения находит ЛОЖНЫЕ срабатывания на каждом корректном calink-матче (несовпадение
  заголовка — теперь нормальная форма успешного матча, не признак ошибки). Инструмент
  обновляется в той же задаче: либо убрать `title_mismatch` как признак целиком, либо
  пересчитать «ложность» через ту же пул/eligibility-логику, что и новый matcher (не через
  голое неравенство заголовков). **Явно задокументировать: не запускать `--apply` этого
  инструмента против прода до обновления — иначе он откатит рабочие calink-матчи обратно в
  `FOUND` и потеряет привязку к событию** (это деструктивная операция, `with_for_update` +
  обнуление `calendar_event_*`/`matched_calendar_*`).
- Тесты (новые или переписанные в `tests/test_matching.py`):
  - calink-кейс, оба варианта заголовка файла (дефолтный и переименованный вручную) → auto-match,
    confidence ≥ порога;
  - консультация (Денис/Михаил) → `LOW_CONFIDENCE`, не auto-match, не `NO_COMPATIBLE_EVENT`;
  - «голая» calink-ссылка без `calink.ru` в описании → `LOW_CONFIDENCE` после фикса regex
    (не auto-match, confidence ~0.45);
  - регрессия: `test_reported_non_recruiting_title_cannot_match_other_event` остаётся как есть и
    проходит без изменений (доказывает, что booking-marker-путь не открыл дыру);
  - регрессия: существующий тест на точное совпадение Антона/Лили проходит с тем же confidence;
  - all-day/многодневное событие в пуле не создаёт ложный `MULTIPLE_ELIGIBLE`/
    `UNMONITORED_COLLISION`;
  - `tests/test_rematch_calendar_events.py` обновлён под новую семантику `title_mismatch`.
- `pytest tests/test_matching.py tests/test_scheduler.py tests/test_rematch_calendar_events.py`
  зелёные, реальный вывод в build-отчёте.

## Plan

### Шаги

1. Прочитать `app/tools/calendar.py` (`ParsedVEVENT`, decode all-day/`DTEND`) и
   `tests/test_matching.py` целиком через `ast-index`/Read, чтобы не сломать существующие
   фикстуры и не продублировать уже покрытые кейсы.
2. `app/services/matching.py`:
   - В `score()` (~163-175): построить `compatible` из двух циклов — существующего (exact-title +
     time window) и нового (time window + `BOOKING_PATTERN.search(event.description)`, без сверки
     заголовка). Общий дедуп по `(calendar_id, uid, recurrence_id)`.
   - Добавить проверку длительности события перед добавлением в ЛЮБОЙ из двух путей: пропустить
     событие, если `event.dtend_utc - event.dtstart_utc >= timedelta(hours=20)` (all-day/блок).
   - `INTERVIEW_PATTERN`: заменить `r"собеседование|интервью|interview|candidate"` на
     `r"собеседован|интервью|interview|candidate"` (основа слова вместо полной формы).
   - `_score_event`/веса/остальные паттерны — не трогать.
3. `tests/test_matching.py`: добавить/переписать тесты по списку в Acceptance criteria. Не менять
   ожидание `test_reported_non_recruiting_title_cannot_match_other_event` — он обязан пройти
   без изменений, это и есть доказательство, что защита сохранена.
4. `tools/setup/rematch_calendar_events.py`: убрать или пересчитать `title_mismatch`-эвристику
   (строки ~41-46 и далее по использованию) так, чтобы она не считала нормальный calink-матч
   (несовпадающий заголовок + валидный пул/eligibility) ложным срабатыванием. Обновить
   `tests/test_rematch_calendar_events.py` под новую семантику.
5. `app/scheduler/cron.py`: не трогать — `title_exact` на line ~1315 остаётся
   диагностическим полем трейса (не гейтом), полезен и дальше для различения calink/exact матчей
   в логах.
6. Прогнать `pytest tests/test_matching.py tests/test_scheduler.py
   tests/test_rematch_calendar_events.py -q`, затем полный `pytest -q`. Прогнать `ruff check`/
   `mypy` на изменённые файлы.
7. Обновить `.memory-bank/current-work.md` раздел 3 — пометить реализованным, с итоговыми
   confidence-числами по реальным кейсам Лили.

Нет. Открытый вопрос скептика про `UNMONITORED_COLLISION` при нескольких календарях у будущих

## Out of scope

- Расширение `NAME_PATTERN`/`INTERVIEW_PATTERN`/весов под кейсы Дениса/Михаила — нет подтверждения
  рекрутера, что это вообще собеседования; у Лили много некандидатских встреч 1:1 в том же
  календаре, риск ложных авто-матчей.
- Изменение `FILENAME_PATTERN` — формат уже верно парсится.
- Изменение `confidence_threshold`.
- Проверка `UNMONITORED_COLLISION` при множественных календарях для рекрутеров, кроме Лили
  (у неё один календарь, не затронуто) — отдельная задача перед включением фичи для Антона или
  будущих рекрутеров с несколькими календарями.
- Любая интеграция с Notion/Mattermost/Synology — это только слой сопоставления записи с
  событием.

## Assumptions

- «Опционально» в старой заметке current-work.md про доп. сигнал title-match — не реализуется:
  booking-marker путь уже даёт confidence ~1.0 без него, а лишний сигнал меняет числа во всех
  существующих тестах без явной необходимости (риск регрессии порогов без пользы).
  `rematch_calendar_events.py` фикс — через удаление/пересчёт `title_mismatch`-эвристики, не через
  более сложный редизайн инструмента (меньший, более безопасный диф).
- Все реальные паттерны имени файла (`YYYY-MM-DD_HHMMSS_<title>.webm`) уже покрыты
  `FILENAME_PATTERN` — подтверждено на 94 файлах Лили, доп. парсинга не требуется.
